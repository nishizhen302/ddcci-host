# 216pin 机型 DDC/CI 协议（从固件逆向）

来源固件：`C0105-00080(LG)_V110_0x11_260720.bin`（576 KB = 9 个 64 KB bank，Realtek 8051 分 bank 镜像，
公共区 0x0000~0x2C21 每 bank 一份）。没有源码，全部结论来自反汇编；**"推断"标记的条目只看出了数据流向，没看出业务含义，要实机确认**。

## 1. 链路参数

| 项 | 216pin（本固件） | 156pin 南微（现控制台） |
|---|---|---|
| 从机地址 | **0x6E**（读 0x6F），标准 DDC/CI | 0x5E（读 0x5F）|
| 发送校验 | chk = 0x6E ^ 后面所有字节 | 同算法，种子 0x5E |
| 回读校验 | chk = 0x50 ^ 回复各字节 | 同 |
| 总开关 | OSD「DDC/CI」开关（`ECE5.bit4`），**关着就整帧丢弃，不回任何东西** | — |

- FF23（DDC/CI 从机地址寄存器）只会被写成 0x6E 或 0x6A。0x6A 是 Realtek 调试/ISP 模式，和这里无关。全固件里没有任何地方把 0x5E 写进地址寄存器。
- 0x6E 是标准地址，所以 **Windows dxva2（`ddcci.py`）理论上能直接打到这台机**，不必走 USB 小板或 nvapi。
- 帧在接收缓冲区里的布局（XDATA `EAA4` 起）：`[0]=51 [1]=0x80|len [2]=命令字 [3]=操作码/子命令 [4] [5] ...`
- 回复缓冲区在 `EB24`：`[0]=6E [1]=0x80|len [2]...`

## 2. 命令字（cmd，帧第 3 字节）

| cmd | 作用 | 处理函数(bank7) |
|---|---|---|
| 0x01 | GET VCP（标准）| 98CF |
| 0x03 | SET VCP（标准）| 678B |
| 0x07 | 时序报告 | DAEB |
| 0x0C | 保存设置（空操作）| — |
| **0xC0** | **厂家自定义，下面有 22 条子命令** | 7C3D |
| 0xC4 | 厂家自定义（未细看）| C805 |
| 0xF3 | capabilities | — |

capabilities 串：`(prot(monitor)type(LCD)model(RTK)cmds(01 02 03 07 0C C0 C2 E3 F3)vcp(02 03 04 05 06 08 0B 0C 10 12 14(01 02 04 05 06 08 0B) 16 18 1A 52 60(01 03 04 0F 10 11 12) 87 AC AE B2 B6 C6 C8 CA CC(01 02 03 04 06 0A 0D) D6(01 04 05) DF FD FF)mswhql(1)asset_eep(40)mccs_ver(2.2))`

## 3. 标准 VCP（cmd 0x01 / 0x03）

帧：写 `6E 51 84 03 op hi lo chk`；读 `6E 51 82 01 op chk` → 从 0x6F 读回 `6F 6E 88 02 rc op type maxH maxL curH curL chk`（rc=01 表示不支持该码）。

SET 支持：02 03 04 05 06 07 08 0A 0C 0E 10 12 14 16 18 1A 20 30 52 60 6A 6C 6E 70 72 87 CA CC D6 FC
GET 支持：02 04 05 06 07 08 0B 0C 10 12 14 16 18 1A 1E 20 30 52 60 6C 6E 70 72 7E 87 AC AE B2 B6 C6 C8 C9 CA CC D6 DF ED EF

**和 156pin 不同的地方（直接影响控制台）：**

| 操作码 | 216pin | 156pin |
|---|---|---|
| 0x10 亮度 / 0x12 对比度 | 0~100，相同 | 0~100 |
| 0x14 色温 | **MCCS 标准值**：01=sRGB 04=5000K 05=6500K 06=7500K 08=9300K 0B=User | 05=User 06=9300K 08=6500K |
| 0x72 gamma | SET：01=关 02→档7 03→档6 04→档4 05→档2 08→档1；GET 回 档位+1（01~08）| 06~0C = gamma1~7 |
| 0xE0 硬件版本 | **不支持**（GET 回 rc=01）| 支持 |
| 0xC9 软件版本 | 固定回 0x0001（max 0xFFFF）| 支持 |
| 0xC8 | 0x09（Realtek）| — |

⚠ 0x72 的 SET 和 GET 映射对不上（写 02 读回 08），这是厂家固件自己的问题。**控制 gamma 建议用下面的 `C0 91`**，读回用 GET 0x72 拿档位（读回值 − 1 = 档位）。

固件内部色温档位（结构体 `EC89+0x16·n` 第 0 字节 bit3~5，Realtek 标准枚举）：0=9300K 1=7500K 2=6500K 3=5000K 4=sRGB 5=User。

## 4. 0xC0 自定义子命令（这台机的"另一套协议"）

帧：`6E 51 84 C0 sub v1 v2 chk`（数据多的子命令把长度字节加大，见各条）。
- 子命令在 `RX[3]`，参数从 `RX[4]` 起。
- **固件不检查 0xC0 帧的校验和**（只有 9F 检查），但上位机照常算，免得以后固件改了。
- 每条子命令处理完默认回一帧 ACK：`6F 6E 86 C2 00 00 84 98 01 chk`。97/9A/9E/71 关掉 ACK，自己回数据（见表）。上位机可以读也可以不读。
- 除 0x71 外，每条 0xC0 帧都会重启一个参数为 60000 的事件（0x23），猜是"DDC 控制中"的 60 s 超时。

| sub | 参数 | 作用 | 把握 |
|---|---|---|---|
| **0x90** | v1 = 0~100 | **亮度**（和 VCP 0x10 同变量、同函数，1.5 s 后存盘）| 确定 |
| **0x95** | v1 = 0~100 | **对比度**（和 VCP 0x12 调用链相同）| 确定 |
| **0x92** | v1 = 0~4 | **色温档位**：0=9300K 2=6500K 3=5000K 4=sRGB；1 被改成 2（无 7500K）；≥5 按 0 | 确定 |
| **0x91** | v1 = 0~6 | **gamma1~7**（写入档位 v1+1；7 也是档7；≥8 按档1）| 确定 |
| **0x96** | v1=键 v2=模式 | **模拟按键**，见第 5 节 | 确定 |
| 0x98 | — | ping，只回 ACK | 确定 |
| 0x9A | — | 回 `6E 87 C2 00 00 85 9A 00 04 chk`（固定 00 04，像协议版本/机型号）| 确定 |
| 0x71 | — | 回 `6E 8C C0 00 00 8A 71 [F028] [a_hi a_lo] [b_hi b_lo] 00 [FF4B] chk`：芯片寄存器 F028/FF4B + 两个 16 位量（像芯片/固件 ID）| 推断 |
| 0x97 | — | 回 0x2B 字节测试图样 `C2 00 00 11 22 33 44 …00 01 02…23`（链路自检）| 确定 |
| 0x9F | v1=长度(≤25) 后跟 25 字节 | **校验和正确才执行**，写入 25 字节信息，ACK 的最后字节 = 1 成功 / 0 失败 | 推断（序列号/型号一类）|
| 0x9E | — | 回 `6E 9E C0 00 00 9C 9E [14 字节][11 字节] chk`，与 9F 配对读回 | 推断 |
| 0x55 / 0x56 / 0x57 | v1 | 写递增三元组 ECC6 < ECC7 < ECC8（各带钳位 ≤FB / ≤FD / ≤FF），对应 VCP 0x6C/0x6E/0x70 读回的同一组变量；当前 gamma 档位 = 8 时改写另一组 ECF4~ECF6 | 推断：背光 PWM 三点（亮度 0/50/100 对应的 PWM）|
| 0x9D | v1 | 直接按 v1 输出背光 PWM（预览，不存盘）| 推断 |
| 0x9B | v1,v2 | 改 ECC7（取第二个参数），10 ms 后存盘 | 推断 |
| 0x99 | 3 个 16 位大端值（各 ≤0x3FFF）| 送进 bank6 B1D2 | 推断：RGB 三路增益一类 |
| 0xF1 | v1 = 1 / 其他 | 整体切换一套图像参数（对比度设 50、重载色温/gamma 等），1=进入，其他=恢复 | 推断，名字看不出 |
| 0xF0 | v1 = 1 / 0 | 开关 `ECE2.bit3` 后刷新 | 用途未知 |
| 0xA6 | v1 = 0 / 非0 | 写寄存器 FE30 = 0 / 1 | 用途未知 |
| 0xA3 | v1 = 1 / 其他 | 寄存器 0x0067 bit6 置 1 / 清 0 | 用途未知 |
| 0xE1 | v1,v2 | 调 bank5 DCF9（碰 F029/F02B）| 用途未知 |

## 5. 按键 `C0 96 key mode`

**mode = 00：注入一次按键消息**（和 156pin 的 `C0 96 key 00` 一样）
- 先松开所有"按住"状态，再把 key 写进 OSD 按键消息变量（`EDEA`）
- key = 0~3 时 **1 和 2 互换**（发 1 得到消息 2，发 2 得到消息 1）
- key = 4 不直接写消息，改走一个 100 ms 定时事件（0x11）——OK 键是不是这样实现的要实机确认
- key = 5~15 原样写入
- **key ≥ 0x10：只松开，不发任何键** → 推荐用 `C0 96 FF 00` 当"松开"

**mode = 01：模拟物理键按住不放（216pin 新有的）**
- 写入一个物理按键掩码（`EDE0`）并置位 `22.7`。ADC 按键扫描每轮都会用它**覆盖真实按键**，所以固件的长按、连发、组合键逻辑全都会生效
- 一直按着，直到发一条 mode 00 的帧
- key → 掩码 → 最终按键消息：

| key | 0 | 1 | 2 | 3 | 4 | 6 | 8 | 9 |
|---|---|---|---|---|---|---|---|---|
| 掩码 | 02 | 03 | 05 | 30 | 08 | 0A | 04 | 06 |
| 消息 | 0 | 1 | 2 | 3 | 4 | 6 | 8 | 9 |

按 156pin 的叫法：0=Menu 1=Right 2=Left 3=Exit 4=OK（216pin 上左右哪个是哪个要实机按一下）。
长按示例：`C0 96 00 01`（按住 Menu）→ 等 N 秒 → `C0 96 FF 00`（松开）。

真实按键表（按 ADC 电压区间）：FF09 通道 01~1F→03、41~4F→04、79~87→02、A1~AF→05；FF0A 通道 01~1F→06、79~87→0A、A1~AF→30。
掩码 → 消息的完整解码表（bank8 85F5）还有 01→17、07→18、09→05、0B→0A、0C→0B、0D→0C、0E→0D、20~27→0E/0F/10/11/12/04/14/15，mode 01 那张表打不到这些码。

## 6. 控制台里的实现（2026-10-12 已做，待实机验证）

扫描自动识别为 216pin（GET 0x72 max=0x08 / 0x14 max=0x0B）并选中该目标后：只扫 0x6E；亮度/对比度走 VCP 0x10/0x12；色温走 VCP 0x14（MCCS 值，6 档）；
gamma 写 `C0 91`、读 GET 0x72 减 1；版本只读 0xC9；隐藏 156pin 的工厂/老化宏，换成「长按」行
（选键 + 秒数，按住时 RIGHT/LEFT 用互换后的编号 2/1，保证和点按是同一个键；结束必发 `C0 96 FF 00`，
关窗时也补发一次）。代码：`nanwei_core.Monitor216`、`app_nanwei.Api.select_model/hold_key`、`ui/nanwei/app.js` 机型选择段。

**面板 7 键（2026-10-12）**：OSD 按键区按 `nanwei_core.KEYPAD_216` 渲染 7 个键，编号 1~7 = 消息号 0/1/2/3/6/8/9，
点按发 mode 00（1/2 互换后的值），长按发 mode 01（直接发消息号）。只有 1=MENU、4=EXIT 能确定，
其余功能待实机逐个按一下确认后改表里的 `label`/`hint`。界面不显示 156pin/216pin 字样。

原始改造清单：

1. 地址切到 0x6E（GUI 里已经有 0x5E/0x6E 切换）。
2. 色温、gamma 的值表按机型分开（第 3 节的表），或者干脆改走 `C0 92` / `C0 91`。
3. 版本读取：0xE0 不支持，改读 0xC9，或者用 `C0 9A` / `C0 71`。
4. 按键沿用 `C0 96 key 00`；另外可以加"长按"（mode 01 + 松开帧），156pin 做不到的长按类宏可以在 216pin 上试。
5. 连不上时先确认 OSD 里 DDC/CI 开着。
