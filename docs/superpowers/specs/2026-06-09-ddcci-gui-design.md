# DDC/CI 控制 GUI · 设计文档

**日期:** 2026-06-09
**状态:** 已通过评审,待进入实现计划
**关联:** 上位机 `ddcci.py`(已打通),固件侧 `project_ddcci_control`(VCP 0x72 gamma 已验证)

---

## 1. 目标

把现有命令行工具 `ddcci.py`(纯 ctypes 走 dxva2 的 DDC/CI 控制)包装成一个**现代、简洁、有科技感**的桌面 GUI。当前先做**雏形**,但架构要为后续大量调试/自定义功能预留扩展位。

**定位:两者兼顾** —— 主面板是简洁常用控制,后续会扩展出"高级/调试"区(本期雏形不实现,但架构需支持)。

---

## 2. 雏形功能范围

| 功能 | VCP | 控件类型 | 固件状态 |
|------|-----|---------|---------|
| 显示器列表 / 选择 | — | 下拉 | 现成(enum) |
| 信号源 | 0x60(只读展示) | 信息条 | 待验证 |

| Gamma | 0x72 | 分段按钮 + 实时曲线 | ✅ 已验证 |
| 亮度 | 0x10 | 滑块 + ± 微调 | ✅ 已验证 |
| 对比度 | 0x12 | 滑块 + ± 微调 | 待验证 |
| 色温 | 0x14 | 分段按钮(配暖→冷渐变条做指示) | 待验证 |

"待验证"项:界面照常发命令,读不回则显示"未响应",不阻塞框架。

## 3. 技术栈

- **pywebview + HTML/CSS/JS**(Win11 自带 Edge WebView2),Python 后端。
- 后端**直接复用** `ddcci.py` 的 dxva2/ctypes 逻辑。
- 前端纯 HTML/CSS/JS,不引第三方 UI 框架(保持轻量,和现有"零三方依赖"风格一致;pywebview 是唯一新增 pip 依赖)。
- 可用 PyInstaller 打包成 exe(后续)。

---

## 4. 架构(四层 + 可插拔后端)

```
backends/                可插拔通信后端 (实现统一 Backend 接口)
  ├ dxva2_backend.py     Backend A: Windows 标准 DDC/CI (dxva2), 地址 0x6E, 走独显 ← 雏形
  └ (debugger_backend.py Backend B: 硬件调试器/低层 I2C, 自定义地址(0x5E 等) ← 未来)
      │
ddcci_core.py   选定后端, 提供统一 API: enum_monitors / get_vcp / set_vcp / read_caps
                (从 ddcci.py 抽取, 无 CLI / 无界面, 可独立单测)
      │
app.py          pywebview 启动窗口 + JS 桥; 暴露 API 给前端;
                选显示器/选后端/错误捕获/状态翻译
      │
ui/             index.html + style.css + app.js (即界面)
```

**职责边界:**
- `backends/` —— 每个后端实现同一个 `Backend` 抽象(`enum / get_vcp / set_vcp / read_caps`)。换通信通道 = 换实现,上层不变。
- `ddcci_core.py` —— 只懂 DDC/CI 语义,不懂界面、也不绑死某条物理通道。
- `app.py` —— 桥接层。把核心方法暴露成 `window.pywebview.api.*`;捕获异常,把"读不到/设失败"翻译成前端可显示的状态对象。
- `ui/` —— 只懂展示与交互,通过 JS 桥调后端,不碰 ctypes。

`ddcci.py` 原 CLI 保留不动(抽取核心后,CLI 可改为薄壳调用 `ddcci_core`,或暂保持现状)。

## 5. 通信后端与寻址(关键约束)

DDC/CI 在 I2C 总线上的标准显示器地址 = **0x6E**(7-bit 0x37)。Windows 的 dxva2 (`SetVCPFeature` 等)**写死打到 0x6E,不给改地址的口子**。用户的板子有时配在 **0x5E** 应答,dxva2 物理上够不着。

因此分两条通道,经 Backend 接口抽象:

| 后端 | 通道 | 寻址 | 状态 |
|------|------|------|------|
| **A · dxva2** | 独显 DDC 线 / Windows 标准 DDC/CI | 固定 0x6E | **雏形实现**(复用 `ddcci.py`) |
| **B · 硬件调试器 / 低层 I2C** | 外接 I2C 调试器(走其 SDK/驱动) | **可自定义**(0x5E 等) | 未来实现,接口预留 |

- 雏形只接 **Backend A**;UI 预留"**通信后端 + 地址**"选择位(雏形里地址项灰显/锁 0x6E),Backend B 落地后即启用。
- **核显(iGPU)常不暴露 DDC/CI** —— 这是用户"核显不通、独显通"的根因。属环境/接线问题,由错误处理给出提示,不是地址问题。

## 6. 可扩展性 · caps 驱动的动态控件(核心设计)

控件**不写死**,而是**运行时由所选显示器的 capabilities 驱动**:选定显示器 → `read_caps()` → 解析 caps 串得出"这台支持哪些 VCP" → 据每项生成控件。**不同显示器控件集自动不同**(用户明确需求)。

控件由"描述 + 类型"渲染。基础项可由内置描述表给出友好名/图标/类型,caps 里出现但表中没有的 VCP 落为通用 `raw` 控件:

```js
const CONTROL_HINTS = {  // VCP -> 友好渲染提示; caps 决定是否出现
  0x72: { name:"Gamma",  type:"segment", icon:"gamma",
          options:[{label:"OFF",v:0},{label:"1.8",v:1},{label:"2.0",v:2},
                   {label:"2.2",v:3},{label:"2.4",v:4}] },
  0x10: { name:"亮度",   type:"slider",  icon:"sun" },
  0x12: { name:"对比度", type:"slider",  icon:"contrast" },
  // 色温预设的 v 值据 caps(0x14) 实际回报填入(常见 5000/6500/9300K/User)
  0x14: { name:"色温",   type:"segment", icon:"thermometer", options:[/* 据 caps 填 */] },
};
```

控件类型注册表:`slider`(滑块+±微调)、`segment`(分段按钮)、`stepper`(±步进,调试用)、`raw`(任意 VCP 手输,调试/自定义命令用)。

**新增调试/自定义命令 = 往 hints 加一条 或 直接用 raw 控件**,渲染器据 `type` 自动生成控件并接好读写。这就是后续"加很多自定义功能 / 自定义命令"的地基。

## 7. 切换方式(控件交互)决策

- **连续值(亮度/对比度)= 横向滑块**。
  - 原因:无实体旋钮时,鼠标"旋"旋钮别扭;滑块最直觉。
  - 精调:数字读数**可点击直接输入**,旁边带 **−/+** 微调按钮。
- **离散值(Gamma/色温)= 分段按钮**。
- **调试区(后续)** 连续值可补 `stepper`(逐值精准测试)。
- 旋钮/垂直推子方案因交互别扭,**不采用**。

## 8. 视觉与换肤

- 两套皮肤**都保留**,App 内一键切换(像换肤):
  - **深色极简** —— 近黑灰底(#0d0d0f)、白色强调、绿色状态点。
  - **白底极简** —— 纯白底(#fafafa)、黑色强调。
- 实现:两套 **CSS 变量**(`--bg / --surface / --text / --accent / --border`…),根节点 `data-theme="dark|light"` 切换;记忆上次选择(localStorage 或后端配置文件)。
- 共同语言:大留白、精准排版、单一强调色、`tabular-nums` 等宽数字、放大的等比线性图标(24px)、整体字号偏大一号。
- 科技感元素:顶部链路**呼吸脉冲点**、Gamma **实时 γ 曲线预览**、色温**暖→冷渐变滑轨**、控件 hover/按压微反馈(仅动 `transform/opacity`)。

## 9. 数据流

1. 启动 → `app.py` 用 Backend A 调 `enum_monitors()` → 前端渲染显示器下拉,默认认 `model(RTK)` 那块板(读 caps 匹配)。
2. 选定显示器 → `read_caps()` 解析支持的 VCP → **据 caps 动态生成控件集**(不同显示器不同)→ 读各 VCP 当前值/最大值填初始态;caps 里的接口/分辨率信息显示在信息条。
3. 用户操作控件 → JS 调 `api.set_vcp(vcp, value)` → 当前后端写 → 返回成功/失败 → 前端即时回读确认并更新读数。
4. 切显示器 → 重复 2(控件集随之刷新)。
5. 换肤 → 仅前端切 `data-theme`,持久化。

---

## 10. 错误处理

- 没找到物理显示器 / VCP 读写失败 / 选错显示器 → **顶部状态栏变灰 + 提示文案(含下一步建议)**,不弹炸窗。
- **扫不到可控显示器**(常见于屏接在核显上)→ 明确提示:"请确认屏接在独立显卡输出、且该显卡 DDC/CI 已开"。
- "待验证"VCP 设了读不回 → 该控件标"未响应",其余功能不受影响。
- 状态更新用 `aria-live` 友好提示(遵循 web-interface-guidelines)。
